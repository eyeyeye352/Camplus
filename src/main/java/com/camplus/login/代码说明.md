# 后端 login 模块 代码说明

本模块负责 Camplus 系统的**用户登录**与**用户注册**后端逻辑，采用 Spring Boot + MyBatis 架构。

---

## 目录结构

```
src/main/java/com/camplus/
├── common/
│   └── Result.java                  # 统一响应包装类（泛型 Result<T>）
└── login/
    ├── entity/
    │   └── User.java            # 用户实体类
    ├── mappers/
    │   └── UserMapper.java      # MyBatis Mapper 接口
    ├── service/
    │   ├── UserService.java     # 业务接口
```

## 1. common.Result.java（新增）

统一响应包装类，所有 Controller 返回值均使用此类封装。

```java
Result<T> {
    boolean success;   // 请求是否成功
    String msg;        // 提示信息
    T data;           // 泛型数据体（通常是 User 对象）
}
```

提供三个静态工厂方法：
- `Result.ok(String msg, T data)` —— 成功响应，带数据
- `Result.ok(String msg)` —— 成功响应，不带数据
- `Result.fail(String msg)` —— 失败响应

序列化后的 JSON 结构示例：
```json
{
  "success": true,
  "msg": "登录成功！",
  "data": {
    "userId": 1,
    "username": "tom",
    "passwordHash": "abc123...",
    "email": "tom@example.com",
    "phone": "13800000000",
    "nickname": "Tom",
    "avatarUrl": "",
    "role": 0,
    "status": 1,
    "lastLoginTime": "2024-06-19T10:30:00",
    "loginErrorCount": 0,
    "lockTime": null,
    "createTime": "2024-06-01T08:00:00",
    "updateTime": "2024-06-19T10:30:00"
  }
}
```

## 3. mappers.UserMapper.java + UserMapper.xml

### UserMapper.java 定义的接口方法

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| insertUser(User user) | User 对象 | int（影响行数） | 新增用户（注册） |
| selectByUsername(String username) | 用户名 | User | 按用户名查询用户 |
| selectByEmail(String email) | 邮箱 | User | 按邮箱查询用户 |
| selectByPhone(String phone) | 手机号 | User | 按手机号查询用户 |
| updateLoginErrorCount(Long userId, Integer errorCount) | userId, 错误次数 | int | 更新登录错误次数 |
| updateLockTime(Long userId, LocalDateTime lockTime) | userId, 锁定时间 | int | 更新账号锁定时间 |
| updateLoginSuccessInfo(Long userId, LocalDateTime loginTime) | userId, 最后登录时间 | int | 登录成功：更新最后登录时间 + 重置错误次数为 0 |

### UserMapper.xml SQL 映射要点

```xml
<resultMap id="UserResultMap" type="com.camplus.login.entity.User">
    <id column="user_id" property="userId"/>
    ...
</resultMap>
```

- 解决数据库下划线命名（`user_id`）到 Java 驼峰命名（`userId`）的映射。
- `insertUser` 中 `login_error_count` 默认 0，`create_time`、`update_time` 使用 `NOW()`。
- `updateLoginSuccessInfo` 同时更新 `last_login_time` 与 `login_error_count = 0`。

## 4. service.UserService.java 与 UserServiceImpl.java

### 接口定义

```java
// 注册并返回完整 User 对象（包含后端补全的 userId、role 等）
User registerAndReturnUser(User user);

// 通用登录（用户名/邮箱/手机号任一均可）
User login(String loginAccount, String password);
```

### 业务实现要点

**registerAndReturnUser(User user)**
1. 依次校验 username、email、phone 是否已存在；任一存在则返回 `null`（注册失败）。
2. 初始化默认值：`role=0`、`status=1`、`loginErrorCount=0`、`lockTime=null`、`lastLoginTime=null`。
3. 密码明文 → 调用 `MD5Util.md5Encrypt()` 加密为 32 位哈希字符串，写入 `passwordHash`。
4. 若 username 为空但 email/phone 有值，则使用 email/phone 回填 username 作为登录账号。
5. 调用 `UserMapper.insertUser()` 写入数据库，成功后再通过 `selectByUsername()` 查询并返回完整 User 对象（含自增 userId、createTime 等）。

**login(String loginAccount, String password)**
1. **多账号查询**：依次按 username → email → phone 查询用户，都找不到则返回 `null`。
2. **锁定状态校验**：若 `lockTime != null`，计算 `lockTime + 30分钟` 与当前时间比较：
   - 锁定未满 30 分钟 → 拒绝登录（返回 `null`）。
   - 锁定已满 30 分钟 → **自动解锁**：调用 `updateLockTime(null)` + `updateLoginErrorCount(0)`，重置后继续登录流程。
3. **账号状态校验**：`status != 1`（禁用）→ 返回 `null`。
4. **密码校验**：明文密码通过 `MD5Util.md5Encrypt()` 加密后，与 `user.getPasswordHash()` 比较。不匹配时：
   - 错误次数 +1，调用 `updateLoginErrorCount` 写入数据库。
   - 若累计错误次数 >= 5 → 调用 `updateLockTime(LocalDateTime.now())` 锁定账号。
   - 返回 `null`。
5. **登录成功**：调用 `updateLoginSuccessInfo(userId, now)` 更新最后登录时间并重置错误计数，返回完整 User 对象。

### 常量
- `MAX_ERROR_COUNT = 5`：连续错误 5 次触发锁定。
- `LOCK_DURATION_MINUTES = 30`：锁定持续 30 分钟后自动解除。

## 5. controller.LoginController.java

### 接口

```
POST /login
参数（x-www-form-urlencoded）：
    loginAccount  String  登录账号（用户名/邮箱/手机号任一）
    password      String  明文密码
    rememberMe    String  （前端使用，后端当前未处理）

返回（JSON）：
    成功：{ success: true, msg: "登录成功！", data: { userId, username, passwordHash, email, phone, nickname, avatarUrl, role, status, ... } }
    失败：{ success: false, msg: "账号或密码错误，或账号已被锁定/禁用", data: null }
```

### 关键逻辑

```java
User user = userService.login(loginAccount, password);
if (user != null) {
    return Result.ok("登录成功！", user);   // ← 整个 User 对象放入 Result.data
}
return Result.fail("账号或密码错误，或账号已被锁定/禁用");
```

- **不再写入 HttpSession**：后端不维护会话状态，登录态完全由前端通过 `sessionStorage` 管理。
- **返回完整 User 对象**：整个 User 实体（包含 `passwordHash`）放入 `Result.data`，由前端决定如何使用。
- **参数接收方式**：`@RequestParam`，接收前端 axios 发送的 `x-www-form-urlencoded` 格式参数。

## 6. controller.RegisterController.java

### 接口

```
POST /register
参数（x-www-form-urlencoded）：
    username  String（可选） 用户名
    email     String（可选） 邮箱
    phone     String（可选） 手机号
    password  String          明文密码

返回（JSON）：
    成功：{ success: true, msg: "注册成功！", data: { userId, username, passwordHash, email, phone, nickname, avatarUrl, role, status, ... } }
    失败：{ success: false, msg: "账号信息已存在，注册失败", data: null }
```

### 关键逻辑

```java
User user = new User();
user.setPasswordHash(password);
if (username != null && !username.isEmpty()) {
    user.setUsername(username);
}
if (email != null && !email.isEmpty()) {
    user.setEmail(email);
}
if (phone != null && !phone.isEmpty()) {
    user.setPhone(phone);
}
User registeredUser = userService.registerAndReturnUser(user);
if (registeredUser != null) {
    return Result.ok("注册成功！", registeredUser);
}
return Result.fail("账号信息已存在，注册失败");
```

- 注册成功后**不写入 HttpSession**，与登录保持一致，由前端通过 `sessionStorage` 管理登录态。
- **参数接收方式**：`@RequestParam`，与 LoginController 保持一致。

## 7. util.MD5Util.java

**唯一公共方法**：`public static String md5Encrypt(String pwd)`

- 使用 JDK 内置 `java.security.MessageDigest.getInstance("MD5")`。
- 将输入字符串的字节数组（`pwd.getBytes()`）摘要，转换为 16 进制字符串（每字节 `0` 开头补零 → 固定 32 位）。
- 返回 `null` 表示输入为空或发生异常。
- **注意**：数据库 `users.password_hash` 字段存储的就是此 32 位 MD5 值，比对时使用**同一算法**即可。

---

## 8. util.MyBatisUtil.java（备选工具）

- 使用 `org.apache.ibatis.io.Resources` 读取 `mybatis/mybatis-config.xml` 配置，构建 `SqlSessionFactory`（静态初始化一次）。
- 提供 `getSqlSession()` / `getSqlSession(boolean autoCommit)` 手动获取 SqlSession。
- **设计定位**：login 模块当前业务层使用 Spring 注入的 UserMapper（推荐方式），此工具作为备选方案（方便不依赖 Spring 容器时执行原生 MyBatis 操作，如单元测试或其他模块的独立脚本）。
- 本模块的业务代码**未直接使用**此工具。

## 9. 前后端数据流总图

```
[前端 login.html → login.js]
   |  const { data: result } = await axios.post('/login',
   |      new URLSearchParams({ loginAccount, password, rememberMe }),
   |      { withCredentials: true });
   ▼
[后端 LoginController.login()]
   |  1. 参数绑定（@RequestParam，接收 x-www-form-urlencoded 格式）
   |  2. 调用 UserServiceImpl.login()
   |     → 多账号查询 / 锁定校验(30分钟自动解锁) / 密码 MD5 比对
   |     → 错误累加 / 超阈值锁定 / 登录成功更新信息
   |  3. 登录成功：return Result.ok("登录成功！", user)
   ▼
[后端返回 JSON]
   {
     success: true,
     msg: "登录成功！",
     data: { userId, username, passwordHash, email, phone, nickname, avatarUrl, role, status, ... }
   }
   ▼
[前端 login.js 成功回调]
   |  const user = result.data;          // ← 从 result.data 取 User 对象
   |  sessionStorage.setItem('userId', user.userId)
   |  sessionStorage.setItem('username', user.username)
   |  ...（其他字段）
   |  window.location.href = '/home/index.html'
   ▼
[首页 index.js]
   |  sessionStorage.getItem('username') → 已登录则显示用户名、禁用点击
   |                                未登录则显示"登入/注册"，点击跳转 login
   ▼
[其他模块前端]
   |  通过 sessionStorage.getItem('userId') / sessionStorage.getItem('username') 等获取用户信息
```

**关键变化**：后端不再维护 HttpSession，登录态由前端 `sessionStorage` 全权管理。前端使用 `axios.post` + `new URLSearchParams({对象字面量})` 发送 `x-www-form-urlencoded` 格式参数，后端通过 `@RequestParam` 接收。

## 10. 安全与限制说明

| 项目 | 说明 |
|------|------|
| 密码存储 | 仅存储 32 位 MD5 哈希值，明文仅在传输期间存在；HTTPS 环境下更安全 |
| 账号锁定 | 连续 5 次密码错误锁定，30 分钟后自动解除；可防止暴力破解 |
| 账号禁用 | status=0 时无法登录，用于管理员封禁账号 |
| 参数重复校验 | username / email / phone 任一重复即注册失败，保证唯一性 |
| 前端 sessionStorage | 前端自行维护登录态，刷新页面不丢失（关闭浏览器窗口后清除） |
| passwordHash 泄露 | 当前 `Result.data` 直接返回完整 User 对象（含 passwordHash）；如需优化，可新建 UserVO 排除密码字段 |
