# 前端 login 模块 代码说明

本模块负责 Camplus 系统的**登录与注册页面**，包含登录表单、三种注册方式（用户名/邮箱/手机号）、背景音乐、侧边菜单等 UI 与交互。

---

## 目录结构

```
src/main/webapp/login/
├── login.html       # 登录/注册页面 HTML
├── login.css        # 登录页面样式（含 12 个浮动圆点动画、登录弹窗等）
└── login.js         # 登录/注册交互逻辑与 HTTP 请求
```

---

### 布局要点

- 右上角三个按钮：`.menu-button`（right: 20px）、`.user-button`（right: 100px）、`.music-button`（right: 100px）——其中 `user-button` 与 `music-button` 在**本页面 HTML 中并无 user-button 元素**，但 CSS 保留了样式定义以便首页复用。
- `.menu-overlay` 和 `.side-menu` 通过 `.active` class 控制显隐，不操作时 `pointer-events: none`，避免误触。
- 所有过渡动画使用 `transition: opacity/transform 0.2s ~ 0.4s ease`，保证操作流畅。

## 3. login.js

### 页面加载即执行

| 操作 | 说明 |
|------|------|
| 检查 sessionStorage 登录态 | `sessionStorage.getItem('username')` 存在 → 自动跳转首页（`window.location.href = '/home/index.html'`） |
| 初始化 DOM 引用 | 获取 menuButton、sideMenu、menuOverlay、musicButton、bgMusic、menuLoginBtn、loginContent、registerSelectContent、registerFormContent、registerLink、emailRegisterBtn、phoneRegisterBtn、usernameRegisterBtn、registerForm、registerInput、registerTitle 等元素 |
| 背景音乐自动播放尝试 | `bgMusic.play().catch(...)` 浏览器通常会阻止自动播放，失败时改为 `isMusicPlaying = false` 并显示斜杠 |

### 三个页面切换函数

```javascript
showLogin()                  // 显示登录表单，隐藏注册相关
showRegisterSelect()         // 显示注册方式选择（邮箱/手机号/用户名三按钮）
showRegisterForm(type, placeholder, title)
    // 根据注册类型设置输入框 placeholder 和标题
    // 重置表单值、切换 CSS 显示为 registerFormContent
```

### 音乐控制（与 home/index.js 完全一致）

- `isMusicPlaying` 布尔状态变量。
- `toggleMusic()`：切换播放/暂停 + 显示/隐藏 `.music-slash` SVG 斜线图标。
- `document.body` 首次点击监听：若浏览器阻止了自动播放，则在用户点击后立即启动音乐。
- `musicButton.addEventListener('click', e.stopPropagation() + toggleMusic)`——用户手动开关音乐。

### 菜单控制

- 点击 `menuButton` → `.side-menu` 和 `.menu-overlay` 切换 `.active` class。
- 点击 `menuOverlay`（遮罩层）→ 关闭菜单。
- 点击菜单底部 `menuLoginBtn` → 当前已在登录页，无操作。

### 登录表单提交 ⭐ 核心流程

```javascript
loginForm.addEventListener('submit', async (e) => {
    e.preventDefault();
    const loginAccount = document.getElementById('loginAccount').value.trim();
    const password = document.getElementById('password').value.trim();
    const rememberMe = checkbox ? 'on' : 'off';

    // 参数包装为 URLSearchParams（x-www-form-urlencoded）
    const params = new URLSearchParams();
    params.append('loginAccount', loginAccount);
    params.append('password', password);
    params.append('rememberMe', rememberMe);

    // POST /login
    const res = await fetch('/login', {
        method: 'POST',
        headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
        body: params,
        credentials: 'include'          // 携带 Cookie(JSESSIONID)，服务端会话必需
    });

    const result = await res.json();
    if (result.success) {
        // ↓ 将后端返回的完整用户信息存入 sessionStorage ↓
        sessionStorage.setItem('userId', result.userId);
        sessionStorage.setItem('username', result.username);
        sessionStorage.setItem('email', result.email || '');
        sessionStorage.setItem('phone', result.phone || '');
        sessionStorage.setItem('nickname', result.nickname || '');
        sessionStorage.setItem('avatarUrl', result.avatarUrl || '');
        sessionStorage.setItem('role', result.role || '0');
        sessionStorage.setItem('status', result.status || '1');
        alert(result.msg);
        window.location.href = '/home/index.html';
    } else {
        alert(result.msg);
    }
});
```

**关键字段**：`credentials: 'include'` 是必需项，否则前端请求不会携带 Cookie，后端 Session 无法保持。

### 注册表单提交 ⭐ 核心流程

```javascript
registerForm.addEventListener('submit', async (e) => {
    // 1. 获取注册类型（email/phone/username），已在选择注册方式时通过 showRegisterForm() 设定
    // 2. params.append(password)
    // 3. 根据 currentRegisterType，向 params 追加 email / phone / username 字段
    // 4. POST /register（同登录，使用 URLSearchParams + credentials: 'include'）
    // 5. 成功：
    //    - 所有用户字段写入 sessionStorage（同登录流程）
    //    - alert 成功消息
    //    - 跳转 /home/index.html
    //    失败：alert 错误信息（"账号信息已存在，注册失败"）
});
```

**注册后自动登录**：后端 `RegisterController` 注册成功后会 `session.setAttribute("user", user)`，前端也写入 `sessionStorage`，因此注册完成即视为已登录。

### sessionStorage 字段约定（与 home 模块共享）

| Key | 来源 | 说明 |
|-----|------|------|
| `userId` | `result.userId` | 用户 ID（Long，来自后端） |
| `username` | `result.username` | 登录账号（用户名/邮箱/手机号），**是否登录的判断依据** |
| `email` | `result.email` | 邮箱（可为空） |
| `phone` | `result.phone` | 手机号（可为空） |
| `nickname` | `result.nickname` | 昵称 |
| `avatarUrl` | `result.avatarUrl` | 头像 URL |
| `role` | `result.role` | `0` = 普通用户，`1` = 管理员 |
| `status` | `result.status` | `0` = 禁用，`1` = 正常 |

判断规则：只要 `sessionStorage.getItem('username')` 非空，前端即视为「已登录」。

## 4. 跨模块配合与数据流

```
login.html（用户输入）
   |
   ▼ login.js（前端校验 → fetch POST /login）
   |
   ▼ 后端（LoginController → UserServiceImpl.login() → UserMapper）
   |     ↓ 返回 {success:true, userId, username, email, phone, nickname, avatarUrl, role, status}
   ▼
login.js（写入 sessionStorage 所有用户字段）
   |
   ▼ 跳转 /home/index.html
   |
   ▼ home/index.js（读取 sessionStorage.username）
        → 已登录：显示用户名（菜单底部按钮），不可点击
        → 未登录：显示"登入/注册"，点击跳转 login
```

### 与后端接口对应表

| 前端请求 | 后端控制器 | HTTP 方法 | Content-Type |
|---------|-----------|----------|-------------|
| `fetch('/login')` | LoginController.login() | POST | application/x-www-form-urlencoded |
| `fetch('/register')` | RegisterController.register() | POST | application/x-www-form-urlencoded |

两种接口均返回 `{success, msg, userId, username, email, phone, nickname, avatarUrl, role, status}` 结构的 JSON。

## 5. 设计要点总结

| 要点 | 说明 |
|------|------|
| 登录状态判定 | `sessionStorage.getItem('username')` 是否非空 |
| Session 与 Cookie | `credentials: 'include'` 让浏览器自动携带服务端 `JSESSIONID` cookie，保证后端可通过 `request.getSession().getAttribute("user")` 读取完整 User 对象 |
| 注册三种方式 | 通过 `currentRegisterType` 区分 email/phone/username，后端统一用 `UserService.registerAndReturnUser()` 处理唯一性校验 |
| 响应式 UI | 所有按钮、菜单均使用 CSS transition 动画过渡，无第三方 JS 动画库 |
| 音乐/菜单复用逻辑 | 与 home 模块的 `index.js` 中音乐控制和菜单控制代码结构相同（样式值略有差异，如 music-button 的 right 值 home 页为 180px，login 页为 100px） |
| 登录态互通 | 登录页与首页共用同一套 sessionStorage key（`userId`、`username` 等），其他模块前端可直接读取这些值判断登录态和角色权限 |
